## 前端增强：对话历史气泡流 + 代码块复制
- 后端 `AgentEngine.execute` 已将 user/assistant 消息写入 `SessionManager` 会话；新增只读接口 `GET /api/sessions/{id}/messages`（`HarnessController`，返回 `List<AgentMessage>`）。
- 前端 `ChatView` 重写为聊天气泡流：选/建会话后 `getSessionMessages` 拉取历史渲染（USER 右、ASSISTANT 左 Markdown、TOOL 结果、SYSTEM 折叠）；发送时若无会话则自动创建，发送后乐观追加用户气泡并回拉服务端历史同步；本轮工具调用/Token 置于折叠详情。
- 新增 `Markdown.vue`（marked + DOMPurify 净化），渲染后为 `pre` 注入 hover 显示的复制按钮；回复与技能内容均用 Markdown 渲染。
- `package.json` 增加 `marked@^12.0.2`、`dompurify@^3.1.6`。
- 注意：`AgentLoopResult` 不含 sessionId，故前端发送前确保已选定/创建会话以可回拉历史。

## 修复：前端模型回复不显示 + 记忆文件路径
- 前端 `ChatView.send()` 原发送成功后调 `loadMessages()`（`GET /api/sessions/{id}/messages`）渲染回复，但该接口新增后若后端未重启会 404，导致 `messages` 被清空、回复丢失。改为直接从 `AgentLoopResult.response` 追加 assistant 气泡，`loadMessages` 仅用于切换会话加载历史。
- `FileMemoryStore` 默认记忆文件原写 `~/.uct8086/MEMORY.md`（用户主目录），用户在项目里看不到。改为通过 `HarnessProperties.memoryFile` 配置，默认 `<workingDirectory>/.uct8086/MEMORY.md`（项目 `.uct8086` 目录下，已被 .gitignore 覆盖）。`application.yml` 暴露 `memory-file` 配置项（注释状态）。`FileMemoryStore` 双构造器需在 `HarnessProperties` 构造器加 `@Autowired`。
- 全项目清理用户系统目录依赖：`HarnessCoreAutoConfiguration.loadSkills()` 原从 `~/.uct8086/skills/` + `.uct8086/skills/` 两处加载，现仅从项目 `<workingDirectory>/.uct8086/skills/` 加载（注入 `HarnessProperties`）；同步更新 `SkillRegistry`/`SkillLoader` 注释。`BashTool` 的 `os.name` 非目录，保留。
- `.gitignore` 已含 `MEMORY.md` 与 `.uct8086/`，无需新增。
- 已知限制：`AgentEngine` 用 Spring AI `ChatClient.call()` 内置工具循环，`AgentLoopResult.toolCalls` 恒为空（`List.of()`），前端“工具调用”详情为空；若需展示需在 `HarnessToolCallbackAdapter` 记录每次调用。
