# 代码审查指南

## 审查要点

### 1. 功能正确性
- 逻辑是否正确实现需求
- 边界条件是否处理
- 异常路径是否覆盖

### 2. 代码质量
- 命名是否清晰且有意义
- 方法长度是否合理（建议不超过 50 行）
- 是否有重复代码（DRY 原则）
- 注释是否充分

### 3. 安全性
- 输入是否经过校验
- 是否存在 SQL 注入、XSS 等风险
- 敏感信息是否泄露

### 4. 性能
- 是否有不必要的循环嵌套
- 数据库查询是否优化
- 是否有内存泄漏风险

## 审查流程
1. 先理解需求，再审查代码
2. 先看整体结构，再看细节
3. 提出建设性意见，而非批评
4. 标注问题严重程度：[必须修改] / [建议修改] / [可选优化]
