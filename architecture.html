四、三大关注点详解

🔐 鉴权（Authentication & Authorization）

现状：HTTP 层无鉴权
  • HTTP API 层：完全裸奔，无 Spring Security / Filter / Interceptor
  • 任何能访问 9081 端口的人均可调用 /api/chat 执行 Bash、读写文件
  • 仅存在工具执行层权限：DefaultPermissionChecker
  • 4 种模式：DEFAULT(写需确认) / AUTO(全放行) / PLAN_MODE(禁写) / READ_ONLY(只读)
  • 危险命令黑名单：rm -rf、mkfs、DROP TABLE 等
  • 路径规则：deny /etc、~/.ssh、~/.aws 等敏感目录
PermissionChecker.check(tool, args, ctx) → 模式判断 → 危险命令扫描 → 路径规则匹配 → allowed / denied / askUser
建议建设：
① Spring Security + API Key Filter（X-API-Key 头）
② JWT Bearer Token 鉴权（对接企业 SSO）
③ RBAC 角色控制（admin/developer/viewer）
④ 请求审计日志 + 速率限制
⑤ 区分「API 调用方鉴权」与「工具执行授权」两层

🔌 MCP 集成（兄弟团队服务）

现状：Stub 占位实现
  • McpClientService：方法体均为占位，返回空列表/未实现字符串
  • 已引入依赖 spring-ai-mcp（pom.xml）
  • 能力：listServers() / listTools(server)
  • callTool(server, tool, args) / readResource(server, uri)
  • 支持 stdio / HTTP 两种传输（设计层面）
  • 接入点：ToolRegistry 支持动态注册，MCP 工具可挂载进去
兄弟团队 MCP Server ↓ listTools() 发现能力 McpClientService.callTool(server, tool, args) ↓ 注册为 HarnessTool ToolRegistry.register(mcpTool) ↓ Agent 可像内置工具一样调用
建议建设：
① 基于 Spring AI MCP Client 实现真实连接
② application.yml 配置多 MCP Server（兄弟团队服务清单）
③ 启动时自动发现 MCP 工具并注册到 ToolRegistry
④ MCP 工具同样走权限+Hook 管道
⑤ MCP Server 健康检查 + 断线重连

🧠 记忆管理（Memory）

现状：已实现（文件持久化）
  • FileMemoryStore 实现 MemoryStore 接口
  • 持久化路径：~/.uct8086/MEMORY.md（Markdown）
  • 内存 ConcurrentHashMap 索引 + 文件双写
  • memory.uct8086.ai.MemoryEntry：id / category / content / createdAt / updatedAt
  • 支持分类管理、关键词搜索、增删改查
  • 通过 PromptAssembler 注入系统提示词 additionalContext
  • API：GET/POST /api/memory、/api/memory/search
记忆注入流程： memoryStore.search(keyword) → 作为 additionalContext → PromptAssembler.buildSystemPrompt(ctx) → "Additional Context" 段落拼入系统提示词 → LLM 据此决策
建议增强：
① 向量化检索（Embedding + 相似度）替代关键词匹配
② 接入向量库（Milvus/PgVector）
③ 会话历史持久化（当前 SessionManager 仅内存，重启丢失）
④ 记忆衰减/过期机制
⑤ 按 session/user 维度隔离记忆
